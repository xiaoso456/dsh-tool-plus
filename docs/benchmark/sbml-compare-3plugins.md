# SWE-bench Multilingual · 三种工具面运行对比（muse-spark-1.2）

> 同一个模型、同一批题、同一个驱动器，只换工具面与调用模式。三组各跑三轮。

## 1 实验条件

| 项 | 值 |
|---|---|
| 数据集 | SWE-bench Multilingual，首批 20 题抽样（Rust / Java / Go / TypeScript 为主，含 feature 类）|
| 题量 | 每组每轮 20 题 |
| harness | DSH 0.2.2-rc.5 + Node 24.22.3 |
| 模型 | muse-spark-1.2-contributor（opencode.ai 渠道）|
| 思考强度 | high |
| 上下文窗口 / 最大输出 | 1,048,576 / 131,072 |
| 并发 | 2 |
| 轮次 | 每组 3 轮，六组合计 360 次运行 |
| 插件版本 | dsh-ops 0.5.5、tool-plus 0.3.0-beta.3 |
| 运行方式 | DSH 跑在实例容器内，改动直接落 `/testbed`，`git diff --cached` 即补丁 |
| 判分 | 官方 harness `swebench.harness.run_evaluation` |

各组工具面构成：

| 工具类别 | 官方工具面 · 标准（23 个） | dsh-ops · 标准（24 个） | tool-plus · 标准（22 个） |
|---|---|---|---|
| 命令执行 | bash | bash | bash |
| 读文件 | read、read_image | ops_inspect_local_file、read_image | read |
| 搜索 | glob、grep | ops_glob、ops_grep | glob、grep |
| 写 / 改 | write、edit | write、edit | write、edit |
| 后台任务 | job_list、job_output、job_kill | 同左 | 同左 |
| 子代理与消息 | subagent、subagent_fork、send_message、list_agents、wait_agent | 同左 | 同左 |
| 目标与笔记 | create_goal、get_goal、update_goal、todo_write | 同左 | 同左 |
| 网络 / 技能 / 工作流 | web_fetch、skill、workflow、working_directory | 同左 | 同左 |
| 工具发现 | — | ops_discover_tools | — |
| 待办 | todo_write | todo_write | todo_write |

- **dsh-ops 0.5.5**：读文件、搜索三件（`read`/`glob`/`grep`）换成 `ops_inspect_local_file`/`ops_glob`/`ops_grep`，另加 `ops_discover_tools`；`bash` 与其余工具保持宿主原生。
- **tool-plus 0.3.0-beta.3**：工具名基本不变，实现由插件接管；`read_image` 并入 `read`，工具数 -1。
- **三个 PTC 组**：对外只暴露 1 个 `run_code`，上表所有工具在代码块内可调用。系统提示词 + 工具定义 token 分别为 6,915（官方 PTC）、6,915（dsh-ops PTC）、7,463（tool-plus PTC）。

口径：

- 步数 = 实际请求次数；工具调用 = `tool/call` 事件数，时长取 `tool/call` 到对应 `tool/result` 的墙钟，同一步并行调用取区间并集。
- token 取上游 usage 精确值：**输入** = 未命中缓存部分，**缓存读** = 命中部分，**输出** = 含思考。`totalTokens` 是每步上下文量不是累计值，合计按输入 + 缓存读 + 输出逐题求和。
- 花费按每百万 token $0.10 输入 / $0.002 缓存读 / $0.20 输出折算。

### 5.2 系统提示词与工具定义

系统提示词与工具定义每步重发一次，「单步固定开销 × 步数」就是它在一次运行里被重复计费的总额。

| 组 | 暴露工具数 | 系统提示词 token | 工具定义 token | 单步固定开销 | 固定开销合计/题 | 占总 token | 除固定开销外 token/题 |
|---|---|---|---|---|---|---|---|
| 官方工具面 · 标准 | 23 | 563 | 4,335 | 4,898 | 157,063 | 9.9% | 1,430,632 |
| 官方工具面 · PTC | 1 | 6,401 | 514 | 6,915 | 193,274 | 13.0% | 1,294,595 |
| dsh-ops · 标准 | 24 | 848 | 5,229 | 6,077 | 221,405 | 13.8% | 1,383,340 |
| dsh-ops · PTC | 1 | 6,401 | 514 | 6,915 | 179,329 | 13.8% | 1,123,977 |
| tool-plus · 标准 | 22 | 580 | 4,903 | 5,483 | 195,926 | 15.2% | 1,095,954 |
| tool-plus · PTC | 1 | 6,949 | 514 | 7,463 | 244,289 | 16.7% | 1,215,231 |

`单步固定开销 = 系统提示词 token + 工具定义 token`；`固定开销合计/题 = 单步固定开销 × 步/题`；`除固定开销外 token/题 = token 合计/题 − 固定开销合计/题`。

固定开销占 token 总量 9.9%–16.7%。tool-plus 的固定开销最高：标准模式比官方多 24.7%，PTC 模式多 26.4%（提示词正文 6,949 token，比官方 PTC 的 6,401 多 8.6%）。

## 7 行为分析

### 7.1 标准模式：回吐越细，往返越多

工具调用构成（次/题，同类工具已合并）：

| 组 | 命令执行 | 读取 | 搜索 | 写改 | 后台任务 | 其它 | 合计 |
|---|---|---|---|---|---|---|---|
| 官方工具面 · 标准 | 14.3 | 9.9 | 4.6 | 4.6 | 0.7 | 0.5 | 34.6 |
| dsh-ops · 标准 | 16.8 | 13.3 | 5.4 | 3.2 | 0.7 | 0.3 | 39.8 |
| tool-plus · 标准 | 14.6 | 14.6 | 4.7 | 4.4 | 0.6 | 0.7 | 39.5 |

单步特征：

| 组 | 步/题 | 调用/步 | 输入 token/步 | 每步回吐 token | 工具秒/次 | LLM 秒/步 |
|---|---|---|---|---|---|---|
| 官方工具面 · 标准 | 32.1 | 1.08 | 1,806 | 1,429 | 2.3 | 3.8 |
| dsh-ops · 标准 | 36.4 | 1.09 | 1,560 | 1,107 | 2.2 | 3.5 |
| tool-plus · 标准 | 35.7 | 1.11 | 1,266 | 853 | 1.8 | 3.5 |

三组的调用/步都在 1.1 左右，即几乎每步只完成一个工具动作，差别集中在**一次动作带回多少内容**：

- 官方工具面每次工具回吐 1,429 token，读取调用 9.9 次/题；
- dsh-ops 每次回吐 1,107 token（−23%），读取调用升到 13.3 次/题（+34%）；
- tool-plus 每次回吐 853 token（−40%），读取调用升到 14.6 次/题（+47%）。

读取次数与单次回吐量反向变化，步数随之上移。这就是三组步数 32.1 / 36.4 / 35.7 的来源：**不是模型更啰嗦，而是工具返回的粒度更细**。

落差集中在读取：官方 `read` 每次回吐 3,007 token（整文件），tool-plus 889 token（约半数调用带行范围），dsh-ops `ops_inspect_local_file` 1,660 token。

### 7.2 PTC 模式：一次代码块干多件事

| 组 | 步/题 | 代码块/题 | 内层调用/步 | 输入 token/步 | 每步回吐 token | 单次执行（毫秒）| LLM 秒/步 |
|---|---|---|---|---|---|---|---|
| 官方工具面 · PTC | 27.9 | 27.1 | 1.29 | 2,363 | 1,792 | 3,493 | 4.4 |
| dsh-ops · PTC | 25.9 | 25.0 | 1.43 | 2,414 | 1,866 | 3,536 | 4.1 |
| tool-plus · PTC | 32.7 | 31.8 | 1.29 | 1,646 | 1,229 | **2,664** | 3.9 |

三组都把多个工具动作塞进一次代码块（内层调用/步 1.29–1.43），差别在切分粒度：

- dsh-ops 的代码块最少最重（25.0 次/题、每次 3,536 ms、回吐 1,866 token），步数最少；
- tool-plus 的代码块最多最轻（31.8 次/题、每次 2,664 ms、回吐 1,229 token），步数最多但单步压力最小；
- 官方 PTC 居中，内层调用密度最高（1.29 次/步、每次 3,493 ms）。

### 7.3 步数不是效率指标

| 观察 | 数值 | 说明 |
|---|---|---|
| 步数最多 | dsh-ops · 标准 36.4（+13.6%）| 墙钟 +6.6%、token +1.1% |
| 步数最少 | dsh-ops · PTC 25.9 | 单次执行最贵（3,536 ms）、单步回吐最大（1,866 token）|
| 单次工具最快 | tool-plus · 标准 1.8 s | 与最小回吐量同时出现 |
| 单次工具最慢 | 官方 · 标准 2.3 s | 读取整文件、回吐最大 |

步数只反映往返次数，不反映成本。往返多可以换来更小的单步上下文和更低的账单，往返少则把成本压到单次执行上。

### 8.5 同类工具的差异

- **命令执行**：同一个宿主 `bash`，官方 4,558 ms、dsh-ops 4,277 ms、tool-plus 4,473 ms，最大差 6.6%。调用次数官方 856、dsh-ops 1,008、tool-plus 876，单次回吐分别 551 / 507 / 532 token，三组基本一致。
- **读文件**：三组都在 15–33 ms，但回吐量差 3.4 倍——官方每次 3,007 token（整文件），dsh-ops 1,660，tool-plus 889。tool-plus 约半数读取调用带行范围（`path:50-200`），官方 `read` 不支持行范围。
- **搜索内容**：官方 133 ms、dsh-ops 424 ms、tool-plus 98 ms。回吐方向相反：tool-plus 的 `grep` 每次 2,139 token，是官方 1,653 的 1.29 倍，因为它返回匹配行 + 上下文行（官方只返回匹配行）。
- **搜索文件名**：官方 `glob` 421 ms，比 dsh-ops（148 ms）与 tool-plus（47 ms）慢 2.8–9.0 倍；回吐也最大（官方 369 token/次），tool-plus 用目录分组输出，目录名只写一次，每次 115 token。
- **写文件 / 改文件**：三组都在 8–11 ms；官方 `edit` 有 4 次失败（1.85%，要替换的字符串没匹配上），另两组为 0。
- **后台查询**：10,627–24,544 ms，是单次耗时最长的工具，等的是后台任务本身，与实现无关。
- **失败集中在读文件与命令执行**：官方 `read` 17 次（把目录当文件读）、`bash` 8 次、`edit` 4 次；tool-plus `bash` 15 次（编译/测试非零、命令不存在）、`read` 12 次（路径不存在，含把 `glob` 输出的嵌套目录层漏拼）。
- **dsh-ops 的 0 失败率是口径造成的**：它的 `ops_*` 工具把错误写进返回正文、不以 `Error:` 开头，统计看不到。
- **PTC 的参数缺失几乎全在 tool-plus**：63 次（3.3%），报错文本为 `invalid arguments: missing required property "description"`，缺的是**顶层 `description`**。多数是模型把 `description` 写进了内层 `tools.bash({...})`，顶层就空着。
- **tool-plus 的其余失败类型与基线同量级**：扣除参数缺失 63 次后为 77 次（4.03%），官方 3.69%、dsh-ops 3.54%。
